参考文件实际位于 `F:/myproject/jidian/sign_detect v2.0(1).zip`，不是用户消息中
多了一层目录的 `sign/_detect v2.0(1).zip`。

包中只有识别脚本和串口协议说明，没有新的模型权重。说明中的建议作为参考，

## 对比与改动

| 项目 | 参考 v2.0 | 本次整合 |
|---|---|---|
| 默认画面 | 不画框 | 默认原始画面；持续推理、发 UART |
| BOOT 按键 | 每帧检测按下沿 | 30 ms 非阻塞去抖；长按仅一次；启动时按住先释放 |
| LCD 刷新 | 每次推理后刷新 | 最多 10 fps，与推理循环分开；框/标签/FPS 只在需要显示时计算 |
| 串口顺序 | 画框后发送 | 先发当前帧结果，再绘图/更新 LCD |
| 调试打印 | 每个识别发送帧打印 | 默认关闭；开启后最多每 500 ms 一条 |
| 内存回收 | 每帧完整 gc.collect | 每 200 ms 回收；空闲内存低于 64 KiB 提前回收；每帧释放图像引用 |
| 目标选择 | 五类最高分 | 保留左右专用选择；高分数字/鸣笛不压掉箭头；左右同时出现不猜方向 |
| 框坐标 | 直接使用框中心 | 排除无效/完全画外框，对部分越界框取可见区域中心 |

模型路径、输入 320×240、标签顺序、anchors、阈值 0.2、NMS 0.3、翻转/镜像
0/0 均保持一致。没有改变曝光、颜色、ROI 或模型预处理，避免无数据依据地
改变训练与推理分布。UART 仍是 IO8 TX / IO6 RX，115200 8-N-1，
`$D,class,score,cx,cy#\n`；串口周期至少 100 ms，不保证低帧率下仍能达到 10 Hz。

文档中 cx=320/cy=240 的上界没有照搬：现有 STM32 要求 cx<320、cy<240，
因此候选帧限制到 0..319 / 0..239。关闭框不会关闭识别或改变帧内容。
按钮确认依赖至少两次循环采样，特别短的点击可能因推理耗时未被采到。

## 文件与验证

优化后的路标候选现保存在本目录 `sign_mode34.py`，仍为单文件脚本；部署模式
3/4 时将它复制为 TF 卡上的 `/sd/main.py`。仓库中的 `main.py` 由模式5视觉循迹
使用，两者不能同时作为 CanMV 的自动启动入口。
回退标签 `rollback/2026-09-07-before-k210-v2-display` 指向 `b6e5ff9`。
此前设备上的 K210 脚本保持不变，本轮没有串口访问或烧录。

`tests/sign_line/test_k210_runtime.py` 执行真实 `sign_mode34.py` 的主循环，替换相机、
KPU、UART、LCD、按键和时钟为测试设备，验证：

- 箭头筛选、双箭头歧义、低分/NaN/画外目标拒绝、越界中心处理。
- BOOT 抖动、长按、启动时按住、时钟回绕。
- 开关显示的串口帧完全一致；先 UART 后显示；24 次推理与限频显示/发送分离。
- 默认不逐帧打印；定期 GC 和低内存提前 GC 的分支都运行。
- `tests/sign_line/run.cmd` 完整通过，含现有解析、减速和圆环进出测试。

没有修改 STM32 C 程序，无需重新编译 STM32 来部署该脚本。模拟设备测试
不证明 CanMV 固件 API、实际内存峰值、FPS 或识别准确率；需以后明确授权部署，
通过真实启动日志、BOOT 实按和现场识别对比验证收益。此优化没有重新训练模型，
不会凭空补齐之前数字 1、斜视角或远距离的训练样本。
