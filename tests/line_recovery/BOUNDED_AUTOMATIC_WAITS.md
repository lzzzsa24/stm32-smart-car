# KEY1/KEY2 自动停车有界恢复

用户要求：移除无限停车，即使等待也必须有限。本轮按正在讨论的综合/寻线运行模式
实现。上电 STOP、遥控主动 STOP、切换模式、KEY3/KEY4 单次任务完成后的停止仍保留。
不改中断异常/Error_Handler 等 CPU 故障处理；CPU 不再执行主循环时本策略无法工作。

## 行为

新增主循环统一等待管理，在操作员模式处理之后、驱动故障/绕障/超声波提前返回之前
执行。KEY1/KEY2 只要 DriveBase 持续显示 STOPPED/BRAKING/FAULT 或故障非零，就从
第一次观察开始计时。反复调用 stop、切换自动停车原因都不会刷新计时起点。

| 阶段 | 处理 |
|---|---|
| 自动停车不足 800 ms | 允许原控制器测距、制动或处理故障 |
| 连续达到 800 ms | 保存故障码和原因，取消绕障/位置控制，撤销制动，再清除驱动故障 |
| 随后 1200 ms | 四轮对转，使用原 2493 CPS 搜索目标及原有有界助力，播放预制蜂鸣 |
| 恢复转向结束 | 停止这次恢复，重新初始化寻线和 KEY1 测距，再尝试正常运行 |
| 异常仍持续 | 下一次等待同样有限，再次进行恢复；不会锁存在自动停车 |
| 遥控停止或切换模式 | 先清等待管理和旧电机控制权，立即取消恢复，不会按计时自动启动 |

恢复转向方向优先避开当前红外障碍侧，其次采用当前无歧义外沿/已有恢复方向，缺少
依据时沿用原默认左。恢复窗口固定发布相反方向轮速，不发布前进或后退目标，也不
把中途一帧见线当成立即恢复前进；1200 ms 后重新交给正常控制器。
这个固定窗口是自动故障恢复，不是原丢线搜索的超时截止；正常丢线搜索仍不超时停车。

等待界限依赖主循环服务，实际响应会加上本轮同步 I/O/调度延迟。DriveBase 收到非零
目标但实体车轮堵转不属于程序停车，这种情况下原故障观察/助力继续执行，不能保证
坏电机一定运动。低速原地转向也可能漂移，不能由编码器推断绝对车身轨迹。

## 覆盖及授权取舍

测距 WAIT_SAFE/无效距离、前进速度上限为零、绕障 FAULT、驱动锁存和寻线 STOPPED
只要导致持续停车，都由统一管理恢复，不需要分别删除各模块的局部判断。
有限的普通制动和短暂停顿通常在 800 ms 前结束，不会进入恢复。

按用户本次明确要求，自动恢复会在测距/编码器/绕障故障尚未排除时重新发出转向命令。
原故障会先记录，再清除；它不证明故障已修好。恢复窗口内原绕障/超声波控制器暂时
让出电机，无法把该窗口理解为完整避障保护。遥控 STOP 仍有最高优先级。

## 记录

现有 LSEARCH 新增 source=5（自动等待恢复）及附加字段：
- pause=1：驱动故障；2：绕障故障；3：KEY1 超声波非 FORWARD；4：其他自动停止。
- drive_fault、bypass_fault：释放控制权之前的原始故障掩码。

原搜索记录上述附加字段为零。仍仅在操作员 STOP 后通过既有 f/F 导出，接收至
LSEARCH END。记录在复位/掉电前保留；此轮没有实际连接串口。

## 验证与集成

- 时间策略覆盖 799/800 ms、1199/1200 ms 边界、重复异常、模式禁用及 UINT32 回绕。
- 真实 DriveBase 模拟持续重新发出 STOP，10 秒内产生 5 次恢复且累计转向命令不少于
  5900 ms；左右交替验证四轮对转，无前进目标。
- 实际驱动无运动锁存故障后，显式取消制动/清故障/重新授权可以恢复速度控制。
- STOP 后模拟继续运行 5 秒不再启动；日志导出保留 pause/fault 字段。
- 完整寻线/限速助力/采样/恢复/日志回归及正式编译结果详见交接包。未进行实车验证。
