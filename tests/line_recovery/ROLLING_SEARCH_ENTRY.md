# 模式 2 寻线转向去除停顿

日期：2026-09-07。

用户新观察：模式 2 每转一次停顿一下，要求去除停顿。

## 根因和改动

旧 LineRecovery_Begin 每次丢线都调用整车 BRAKE，进入 REC_BRAKE_SEARCH，
等待制动结束再 COAST 和启动搜索。低速找回期间再次丢线也重复这条路径。
新增真实 DriveBase 回归在修改前复现：反复短暂见线/丢线时出现非 SPEED 状态。
这证明代码有主动插入停轮的路径，不能据此断言它是所有实车慢转的唯一原因。

现在首次丢线、低速找回失败均直接进入搜索，同一控制迭代发出旋转轮速目标。
删除搜索自设的制动阶段；保留 DriveBase 的轮速斜坡/单轮换向过程，不先停整车。
保留开始搜索后的 200 ms 出线方向观察窗口，允许初始白区之后的新外侧边沿更新方向。
不再靠制动的等待时间接收这段边沿证据。

没有提高默认搜索速度 2493 CPS，没有取消正常 4 ms 中间传感器确认、
500 ms 低速移动重入、60 ms 窄线空隙或 100 ms 横线尾部过滤。
500 ms 是边走边确认，并非停车等待；这些参数不在本次调整范围。
中间传感器确认后停止搜索蜂鸣并移动跟线，找回失败继续旋转及蜂鸣。
方向记忆、抗横线干扰、负载补偿、RAM 日志、遥控 STOP/模式切换继续有效。
外部已有 BRAKING 时搜索等待它自然结束，既不取消它，也不提前完成捕获。

KEY1 和 KEY2 共用这个寻线控制器，因此 KEY1 在寻线阶段也得到同样的连续过渡。
KEY1 独立绕障 line_bypass_turn 及其统一制动收尾、超声优先权均未修改。
主循环、DriveBase、电机引脚极性及 PROJECT_STATE.md 均未修改。
