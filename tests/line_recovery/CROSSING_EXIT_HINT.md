# 横线穿越与丢线方向分开处理

本轮父提交 `777c6ef17b6eee13245b04e74a1cf23e6e03ec8e`；集成 HEAD `162324b`，
部署源码 `9f08275` 的寻线部分与父提交等价。用户报告缓速可右转，冲刺丢线仍总左转。

## 复现与规则调整

原横线策略先清方向，再在后续 100 ms 内忽略所有外沿提示。序列“居中加速 1000 ms
→ 三路黑 → 右外侧 1 ms → 全白”即使完整被采到，也会在穿越结束后默认左搜。
新增反例在旧代码上得到 -2493/+2493，断言失败。这是一条与观察相容的路径，尚无
现场同一次原始输入证明所有猛冲都经历了三路/非相邻黑。

现在横线及其后 100 ms 仍只允许低速直行、不立即原地转弯；其中新出现的无歧义
单侧外沿会保存为方向提示。只有穿越窗口结束且持续全白，才使用该方向搜索。
左右对称；没有任何有效方向时仍保留默认左，不声称能凭空推断路线。

三/四路黑及非相邻黑本身仍清除旧方向。若外沿后又出现宽线，提示仍失效。
200 ms 有效期、稳定居中清除、12 ms 立即转弯确认、1 ms 采样、队列交接修正和
ACTIVE 中线触发的一次方向修正规则均保留。本次不改直线速度、电机速度环或极性。

## 可读方向记录

为了以后能区分默认方向与传感器提示，新增 16 条独立 RAM 搜索记录，不依赖电机报错。
记录首次搜索、急弯和 ACTIVE 方向修正；STOP/模式 reset 不清除，复位/掉电/重新初始化
DriveBase 会清除。满后覆盖最旧项并计数，运动期间只写 RAM、不输出串口。

由持有串口授权的集成任务在操作员 STOP 下发送现有 `f`/`F`。原 `LFAULT` 输出之后新增
`LSEARCH BEGIN ...` 至 **`LSEARCH END`**，必须继续接收至后者，不能在 LFAULT END 停读。
一次任务调用至多输出一行；运动时挂起，重新停止后从头导出；重复读取不清记录。

| 字段 | 含义 |
|---|---|
| ms | 决策时 HAL 毫秒计时 |
| side | -1 左，+1 右 |
| source | 0 无有效方向默认；1 方向提示；2 接线沿用；3 急弯；4 ACTIVE 传感器修正 |
| hint | 决策时普通方向提示；ACTIVE 修正时可为旧值，应结合 source 解释 |
| edge / edge_age | 最近无歧义外沿的原始 mask / 距决策毫秒数 |
| wide / wide_age | 最近宽线/非相邻图案 mask / 距决策毫秒数 |
| queue_overwritten | 本次模式开始后采样队列覆盖数量 |

mask 按 X1=1、X2=2、X3=4、X4=8，右外侧单独为 8，左外侧单独为 2。
未出现过对应输入时 mask=0、age=4294967295。记录只证明主控观察到的输入与选择，
不能证明物理 LED/车身轨迹；它不包含完整高速波形，也不等于测得的采样间隔。

## 验证及取舍

左右短闪分别通过实时输入和 Tick 队列重放测试，穿越期间同向、结束后按外沿搜索。
覆盖后来宽线重新清除、居中清除、提示过期、无报警记录、STOP 保留、ACTIVE 改向记录；
日志独立回归覆盖环形覆盖、字段输出、运动禁止输出、中断导出再开始和重复读取。
之前两个“横线后右尾沿也必须默认左”的断言，按本次规则变更更新；不是取消该测试。

新的取舍是：单侧横线尾沿可能影响真正丢线后的搜索方向，但不会在穿越保护期立即
触发对转。四路数字传感器无法证明尾沿一定来自主线，需实际赛道验收。
若仍出现默认左转，应先读取 LSEARCH，检查是否采到 edge=8、是否随后 wide 更近、
是否方向已经过期，避免继续仅凭肉眼灯闪推断频率不足。
