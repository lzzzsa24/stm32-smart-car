# 固定周期采样保留主循环停顿期间的外沿短闪

本轮父提交 `70a47beab56197865354b906ec3b27c4e140a671`；已部署等价寻线源码为
`beb14a3d1d4e43649eada74676d209bcd82b83cf`，集成 HEAD `3768d6c`。
用户观察：每次直线猛冲后，最右侧短闪仍可能进入左搜索。

## 修复路径

原来四路 GPIO 只在主循环调用 line_tracking_read 时读取。OLED 页写入、同步串口输出
也在该循环，期间完整亮灭的外沿不进入控制器。居中方向提示已清空时，全白默认左转。
源码确认存在这种漏采路径；尚无本次现场时序证明它是所有异常的唯一原因。

- 新增 line_sensor_clock.c 覆盖 HAL 提供的 weak HAL_IncTick 扩展点，保留原样的
  `uwTick += uwTickFreq`，随后采样。现有 SysTick_Handler 已调用 HAL_IncTick，当前
  HAL 默认周期为 1 ms。不改共享中断/main/编码器文件，不复用编码器定时器。
- 传感器 GPIO 初始化完成才启动采样，ISR 只读取四路并写入 256 项静态队列。
  每项包括时间和原始掩码；没有电机、蜂鸣、串口、动态分配或等待。
- 主循环每次计算前最多取 256 项，只恢复方向提示、近期中间证据和横线过滤状态。
  使用采样发生时的时间，不把一帧延长成持续黑线；忽略早于上一轮实时观测或超过
  200 ms 的记录。真正转向和捕获命令仍依据当前输入，不重放历史电机动作。
- ACTIVE 恢复状态也按队列顺序读取短暂中线/外沿/全白出线证据，沿用上轮一次修正
  后需新中线证据的规则。横线会清方向并优先结束恢复；100 ms 尾沿过滤保留。
- 队列读取/复位用短 PRIMASK 临界区，恢复进入前的屏蔽状态。满队列保留最新记录、
  累计 overwritten；发现覆盖时清理旧普通方向候选。模式 reset 丢弃旧队列。

## 回归证据

新测试通过真正的 HAL_IncTick 实现和 GPIO 读取模拟输入，在直线加速 1000 ms 后暂停
主循环 5、20、35、50、65、80 ms，期间只给外沿一帧 1 ms 信号；左右方向分别重复
10 轮，中间不 reset。随后主循环只看到全白，仍选中对应搜索方向。

用父提交 line_tracking.c 搭配同一采样测试，方向断言失败、返回 1；本次实现通过。
还覆盖横线与尾沿的时间顺序、ACTIVE 中完整漏采轨迹、历史中线不伪造已捕获、队列
覆盖、reset 清除及计时回绕。2493/1870 CPS 主回归、真实 DriveBase 联合模拟和
RAM 故障日志回归均通过。正式 ARM 编译及链接符号核对由交接包记录。

## 集成和边界

正式构建脚本按 Core/Src 自动纳入新增的两个 .c 文件；STM32CubeIDE 使用
源码目录发现方式时同样应纳入。集成者须确认 ELF 中 HAL_IncTick 为本实现，并调用
LineSensorSample_Tick，不能遗漏 line_sensor_clock.c。

当前默认 1 ms Tick 仍不能保证采到短于周期的任意脉冲；长时间屏蔽中断会延迟采样。
缓存解决方向证据丢失，主循环被阻塞时的电机响应仍可能延迟；没有取消直线提速或
更改目标速度。队列只保留约 256 ms，处理只使用最近 200 ms，覆盖计数仅供调试查询，
本轮没有增加串口导出接口。
