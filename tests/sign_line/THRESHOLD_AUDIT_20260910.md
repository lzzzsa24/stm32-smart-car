主循环先判断停车、再把同一帧交给方向投票。因此首次足够分的箭头不会
被它自己刚刚完成的确认抢先抑制，但此前已由弱帧确认的方向会抑制停车。

## 已确认的问题和取舍

### 1. 方向确认仍可能绕过停车

例如连续 L20、L21、L20 能确认左转，却都没有达到 22% 停车门槛。
确认后即使出现 L22，主循环也因方向非零而不再允许停车。
这是实际代码路径，新增主机测试已复现，不能把此次调到 22% 解释为
“每次确认方向之前一定停两秒”。原 26% 门槛的情况更明显。

本次按要求只改停车门槛。如果必须保证每次选支都有完整停车观察，
应明确增加“本次标志是否已完成停车”的状态约束；只继续降低一个门槛
不能完整表达这个要求。此次没有更改方向确认条件或增加强制停车。

### 2. 置信度不表示距离，22% 可能更早停车

程序未按目标框面积、距离、目标居中程度限制停车，只检查坐标合法性。
远处箭头只要 ≥22% 也会停；降低分数不能保证停车位置更接近标志。
如果实车仍远处停车，需用实测框尺寸/位置设计接近条件，而不能把置信度
当作距离。当前串口只有框中心，没有框宽高，做面积门槛还需扩展协议。

### 3. 只取最高分会发生跨类别竞争

如果错误喇叭框比分数较低的正确箭头高，箭头不会发送；左右候选接近时
也可能交替最高分，导致最后两帧不一致、迟迟不能确认。
这是“每帧仅发送一个最高分标志”的既有选择规则，不是 STM32 又偷偷
加了一层高置信度过滤。本次保留该规则和数字不参与动作的约定。

### 4. 多帧体系主要受时间和稳定性约束，不是分数高

20% 的确认门槛并不高。理想 100 ms 发送间隔下，三帧跨约 200 ms；
但低帧率、插入 NONE/错误类别、坐标跳变或队列丢帧都可能无法凑齐票。
2 秒停车不会自动放宽 600 ms 票窗，也不会累计整个两秒内全部同类帧。
不能在没有实际帧记录的情况下将某次识别失败归因于其中一个条件。

### 5. “帧新鲜”检查不是从曝光开始计时

`vision_uart.c` 在完整协议帧入队时标记 `received_ms`，不是 K210 的曝光
时间。350 ms 和 500 ms 是不同用途的窗口，并不矛盾，但无法检测图像在
K210 推理/发送前已经积压多久。当前脚本发送本次结果降低了缓存重发风险。

### 6. K210 顶部注释有旧描述

`K210/sign_mode34.py` 的说明仍写“同帧两个方向视为歧义”“仅发左右”，
实际函数已是 left/right/horn 最高分单选；THRESHOLD 注释还写“减速”，
当前模式 3 实际是独立停车条件，未设置跟随置信度变化的移动限速。
审核以可执行代码为准。本次没有修改 K210 文件，避免注释变动造成其与
已验证部署脚本的字节哈希不同。

## 出弧角度及其他关键导航门槛

这些量不是置信度，不能和 22% 一起统一调整。以下均保留综合版本已有值。

| 条件 | 值 | 说明 |
| --- | --- | --- |
| 主动出弧，出口侧见线 | 30° | 停车参考下、按方向归一化的上半段正角度 |
| 主动出弧，其他有效窄线 | 40° | 相比旧 55° 已提前 15° |
| 主动出弧最小弧段行程 | 150 mm | 编码器里程条件；仅达到角度不保证立即出弧 |
| 主动条件去抖 | 30 ms | 全白/两侧同时/全黑不能触发；长采样间隔会清掉连续证据 |
| 自然出弧区域证据 | 45° | 与主动 30°/40° 分开，避免“开始转向”等同“已经出弧” |
| 对正 / 中线捕获角域 | ±25° / ±30° | 遵循已有阶段条件；主动转向丢线后首次重新见黑优先释放控制 |
| 自然返回证据 | 上半段峰值 ≥25°，回落 ≥15°，回到 ±40° | 还要求曾经走过下半段、前进及有效窄线 |
| 自然出弧持续确认 | 120 ms、40 mm、航向变化范围 ≤6° | 观察窗内稳定性和行程，不是累计弧段角度 |
| 被动出弧验证上限 | 600 ms / 140 mm | 失败撤销旧导航，不允许补做延迟强制出弧 |
| 入弧选支 / 主动出弧时限 | 2.5 s / 6 s | 超限撤销导航，手动 STOP 保持最高优先级 |
| ARC 时限/里程上限 | 20 s / 3000 mm | 导航异常退出条件，不是新增停车命令 |
| 模式 4 主动出弧门槛 | 60° | 模式 4 独立路径，本任务不改 |

`SIGN_EXIT_EARLY_MIN_MDEG=35°` 的旧回落选出口条件现在被普通出口侧
30° 条件覆盖，实际不再额外提前；属于冗余条件，不是隐藏的 35° 阻挡。
配置中其他入弧/累计角度常量也必须结合 profile 和阶段分支判断，不能
仅看到一个 90°/150° 数字就认为模式 3 又恢复了累计相对角度出弧。
