# 模式 3：单次角度回落不能跳过出弧指令

基线：`19420eaed5fff3d7244dcc41fc1608e1d24ff641`，共享记录的已烧综合版本。
回退：`rollback/mode3-before-exit-dispatch-audit-19420ea`。

用户感觉没有执行出弧，未看清 OLED 阶段。本次实际代码复现了一条确实
不发转向命令的路径，但没有硬件报告，不能认定它覆盖此次实车的全部原因。

## 复现

进入 ARC 后，上半段航向短暂从 55° 回落到 35°，只伴随少量前进计数。
旧代码立即将该单次回落判断为“自然出弧”，转入 EXIT LINE：
`state=8 reason=2 owner=1 targets=1800/1800`。
没有经历 EXIT TURN，也没有执行出弧转向。旧的同类捷径还允许较短的
角度/中线条件跳过转向。外探头灭亮规则只控制成功，不会自动补发被跳过的转向。

## 修复

删除两条绕过完整自然出弧验证的捷径。现在只有既有的完整证据成立，
才能直接交还被动循线：曾经过下半段、上半段峰值和回落成立、前进、
航向变化范围不超过 6°，同时稳定至少 120 ms 且前进至少 40 mm，当前中线有效。

这不是新增角度基准或调整触发门槛；它让原本已有但被提前返回绕过的
验证真正执行。短暂纠偏后仍在弧中，重新满足 30°/40° 触发和去抖时，
应进入 EXIT TURN，真实四轮目标为对应的 0/2200 CPS 向前转向。

用户指定的成功规则保持：出弧流程中仅对应最外侧探头先灭后亮才能成功，
其余三个不参与成功判定。22% 停车、单中间寻线、两秒观察、速度、编码器、
模式 4 保持。此次没有恢复无条件直行，也未删除原有手动 STOP 或导航上限。

## 验证

修改前新增真实路由/跟线/DriveBase 用例失败，见
`manual-build-sign-line-host-test/exit-dispatch-before.log`。
修复后的左右镜像用例确认：短暂 55→35 不跳出 ARC，后续满足条件时实际
转向目标到达 DriveBase，对应外探头事件后同周期清除导航；STOP 有效。
已有自然出弧用例补足实际验证行程，覆盖不强迫真正自然出弧的车辆再转向。
完整回归与正式 ARM 构建见交接包。无串口、烧录或地面验证。
