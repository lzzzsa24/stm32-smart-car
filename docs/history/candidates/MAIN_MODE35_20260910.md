## Scope

- Mode3: slow live tracking, observation centering and two-second hold,
  stopped-heading reference priority and widened exit gates, passive exit
  handoff, horn recognition and route/control trace. No mode4 gyro-tangent
  selection is bound by the promoted adapter. Serial j/J dumps/clears trace.
- Mode5: fast following, constrained forward steering, pulsed counter-turns,
  rolling reacquisition and normal-straight target increase. Existing fixed
  bypass25/30cm/45deg,4000-CPS travel,16/28cm sonar and15cm active-leg guard
  already matched; retained main's configurable isolation from mode1.
- Mode1/2/4: original line/recovery/sign/slowdown/bypass/ultrasonic modules
  retained byte-for-byte. Legacy mode4 adapter and mode2 entry retained.
- Motor polarity, all encoder mappings, audio, reserved Flash, K210 assets
  and operator STOP remain unchanged. Mode3 uses the already deployed SIGN34
  script; no K210 write is needed for this source promotion.

## Isolation and future maintenance

`Core/Inc/promoted_*` and `Core/Src/promoted_*` are namespace-isolated copies
of the requested controller set, mechanically renamed from5940727. They do
not replace the original controllers or create another hardware sampler.
The one existing sensor queue is consumed only by the active mode; mode
switch resets both states and stops previous owners. Shared DriveBase adds
opt-in fast/pulsed assistance and the single HAL tick adds OFF-only pulse
cutoff; ordinary drive calls never opt into these extensions.
The duplicated route module contains unselected mode4 code to retain source
provenance, but the new app adapter always selects STANDARD (mode3).
Likewise the copied mode2 middle-guard API is never enabled in main.
Use tests/check_mode35_scope.py to verify source equivalence and boundaries
before future changes; do not overwrite legacy files with composite versions.
